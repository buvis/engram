# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- **client**: local embedding client - loopback-only config with default shortlist, real-call preflight, on-demand `llama-server` spawn/stop, and batched OpenAI-compatible embedding with model-identity verification
- **store**: sqlite-vec + FTS5 scoped store - model-versioned (fail-loud on model/dim mismatch before any write), scoped BM25 and vector KNN via vec0 partition keys, incremental prune, and per-corpus status (stale/dead detection)
- **chunker**: markdown heading chunker - flat heading-delimited chunks (heading + body with line spans and sequential ordinals), preamble captured, oversized sections kept whole
- **corpora**: corpus enumerators - walk registered repos (gita repos.csv) for prd/decision/discovery sources plus auto-memory dirs (slug-resolved repo, `_unmapped` fallback), git-blob content hashing, and missing-source tracking
- **indexer**: incremental indexer - enumerate and scope-filter corpora, skip unchanged files via content-hash diff, chunk/embed/upsert new and changed files, and prune vanished sources within the reindexed scope only
- **query**: hybrid retrieval - fuse scoped BM25 and vector KNN results via reciprocal rank fusion (RRF), returning ranked file:line pointers; propagates a model mismatch loudly
- **cli**: `engram query|index|status` command line - required-scope query printing file:line pointers, scoped or full `--rebuild` indexing (atomic temp-DB swap), per-corpus status, and a bare `engram` on PATH via `uv tool install`
- **eval**: model-selection harness - score each configured embedding model against a real gold set (top-5 hit rate, deduped by path), compare to an rg baseline, pin the winner into config.toml, and gate on >=80% hit rate strictly beating baseline
- **transcripts**: transcript corpus - enumerate cellar session JSONL and chunk one pointer-addressable turn per kept line, keeping user/assistant text turns plus error-bearing tool results (config-tunable error patterns); a missing cellar path fails loud instead of yielding an empty corpus
- **symbols**: code corpus - enumerate HEAD-tracked files across gita-registered repos (`git ls-files` per repo, missing repos tracked not raised) and chunk each into pointer-addressable symbols via tree-sitter (one whole-symbol chunk per function/class at every nesting depth, body by line span); files with no grammar are skipped and counted for `status`
- **corpora**: register the transcript and code corpora in the index/status/harness pipeline - `engram index` now enumerates and per-corpus dispatches chunking for cellar transcripts and repo code symbols; `engram status` reports the code corpus's grammarless skipped-file count; `index`/`status` surface the producing corpus's own missing-path message instead of a hardcoded repos.csv string; the eval harness accepts `transcripts`/`code` gold entries and includes their files in the rg baseline

- **findings**: review-file parser - extract durable records from review-contract files (frontmatter `reviewers:` plus `Verdict:`/`Tests:` lines), recognising Consolidated-Findings table rows and severity-emoji bullets with their continuation lines; any body line matching neither shape is kept as unstructured record text so no finding content is dropped, and an incomplete or unreadable file fails loud as a total parse failure rather than degrading to a partial record set

- **findings**: durable record store - findings persist as extracted records (`corpus=findings`) that survive their source file, via an atomic `replace_chunks_for_source` keyed on (corpus, path) so a re-harvest replaces a path's records in one transaction, embedding before deleting so a failed embed leaves the prior records intact; findings rows are exempt from reindex pruning and are carried forward (freshly re-embedded from their stored text) across `engram index --rebuild`, which would otherwise destroy them permanently

- **query**: findings hits carry their record text - a `Pointer` for a `findings` hit now exposes the stored record body (`engram query` prints it on its own line after the hit's summary line), so a harvested finding stays readable after its source review file is trashed; every other corpus keeps the pointer-only contract with `body` unset and byte-identical output

- **diffmap**: map a unified diff to the symbols it changes - parse each file section's hunks tracking post-image line numbers, resolve every added line to its smallest enclosing function/class via tree-sitter, and fall back to a file-level entry for module-level edits, grammarless files, pure-deletion hunks, and deleted files (detected by `+++ /dev/null`, the only reliable deletion signal); binary-file and mode-only sections, which git emits with no `---`/`+++` lines at all, contribute nothing and never abort the rest of the parse; the diff and the source files it names are both decoded with replacement, so non-UTF-8 bytes anywhere degrade to replacement characters instead of killing the whole mapping; reads a historical commit's content via `git show` when given a source ref, so reviewing an old range parses that range's source rather than today's worktree

- **query**: two additive retrieval options - `vector` reuses an already-computed query embedding instead of re-embedding the same text (so a caller issuing several scoped queries per subject embeds once, not once per call), and `include_body` surfaces every hit's stored body text rather than only a findings hit's; both default off, so existing callers are byte-identical

- **client**: optional `[pack]` config table - five per-section token caps (`hard_cap_tokens`, `similar_cap_tokens`, `reuse_cap_tokens`, `findings_cap_tokens`, `prose_cap_tokens`) surfaced as `EngramConfig.pack_budget`; an absent or partial table takes documented defaults, and load fails loud when a cap is not a positive integer (a TOML boolean is rejected, not silently read as 1) or when the four section caps plus reserved framing overhead would not fit inside the hard cap

- **pack**: review-pack composer - maps a diff to its changed symbols, reindexes the repo scope first, embeds every changed symbol's text in ONE batched call and reuses each vector across that symbol's four retrievals, then renders Similar code / Reuse precedent / Findings precedent / Task prose into a token-budgeted markdown pack; hits overlapping any changed symbol's span are excluded everywhere (the span union comes from the full symbol list, so a symbol dropped by the per-pack cap still cannot be retrieved as its own "similar" match), item bodies are the store's own indexed text rather than a worktree re-read, each section is trimmed lowest-score-first to its cap under a full tie-break tuple, the rendered file is re-estimated against the hard cap and defensively trimmed until it fits, and the result is published atomically into an out-dir it creates if missing; Task prose fills in a fixed priority order (the capsule's Active Work section, then up to two related memories, then the PRD), every entry truncated to the room the earlier ones left it and the entries ahead of the PRD held to half the prose budget, so an oversized capsule section can neither crowd the PRD out nor push the section past its cap and take the whole thing down with it; portfolio staleness is disclosed in the pack rather than papered over

- **pack**: `engram pack --cycle <id> | --diff <base>..<head>` - a new CLI verb that writes a reviewer context pack for one diff, always reindexing the repo scope first and printing that reindex's own scanned-file and added-chunk counts, so "the index refreshed before the pack was composed" is observable in the output rather than merely asserted; `--cycle` consumes the review harness's staged `review-diff-{id}.diff` against the live worktree, while `--diff` materializes a historical range with `git diff` and parses that range's own content, failing loud without writing a pack when the range errors or resolves to an empty diff; `--prd` and `--capsule` default to the repo's single wip PRD and its project capsule, and each is simply left out of Task prose when missing or ambiguous instead of aborting the run

- **harvest**: `engram harvest <review-file>...` - a fifth CLI verb that ingests review-contract files into the findings corpus, per-file isolated so one path's failure never aborts the batch and never replaces that path's existing records; each path is canonicalized first (relative, absolute and symlinked spellings of one file share one record set), its repo resolved from the git toplevel via the gita registry (with a `claude-home` sentinel for `~/.claude`, which is not a normal working tree); prints one `path/outcome/count` line per file and exits nonzero if any failed

### Fixed

- **client**: recycle a spawned embedding server that starts answering 5xx, not just one returning null vectors - `llama-server` under sustained load degrades into `500 Internal Server Error` on every embed while `/v1/models` still answers 200, and that shape bypassed the recycle path and killed the run outright; a 4xx still fails loud without a recycle, since a bad request is not a sick server
- **symbols**: skip tracked paths that are not regular files when enumerating the code corpus - `git ls-files` lists a submodule gitlink (a directory on disk) and a tracked-but-deleted file just like any source file, and hashing either one raised `IsADirectoryError`/`FileNotFoundError` that aborted the whole portfolio index run
- **cli**: `pack` no longer tells you to "pass `--scope portfolio`" when you run it outside a registered repo - `pack` has no `--scope` flag, so following that advice exited 2 with `unrecognized arguments`; it now names the gita `repos.csv` path and the actual remedy. `query`, `index` and `status`, which do accept `--scope`, keep the original message
- **cli**: `pack --cycle` fails loud when the staged review diff is missing, naming the exact path it looked for and exiting 1 before any indexing happens - it previously ran a full repository reindex (real embedding traffic) and only then died on an uncaught `FileNotFoundError` traceback from inside the diff parser, which is the error case the PRD's own test strategy names
- **pack**: the Task-prose section's related-memory retrieval keys on the PRD's title (its first `# ` heading, falling back to the filename stem) instead of the pack's cycle id or slugged commit range - an opaque id matches nothing in BM25 and is meaningless to the vector leg, so every pack previously carried two arbitrary nearest-neighbour memories as noise; when no PRD is resolved the memory query is now skipped entirely rather than run on the id
- **cli**: `pack` anchors every path it resolves to the git worktree root, not the invocation directory - the staged diff it reads (`--cycle`), the diff it materializes (`--diff`), and the directory it writes the pack into all previously resolved against the current working directory while `--prd`/`--capsule` already anchored to the repo root, so running `engram pack` from a subdirectory failed on a staged diff that exists at the root and scattered its output into `<subdir>/dev/local/tmp/`
- **cli**: `status` exits nonzero on staleness (stale files or dead rows) and lists missing corpus dirs; `index` reports missing corpora instead of discarding them; query scores print at fixed precision; `-k` rejects non-positive values; `index --rebuild` clears a leftover temp DB before building; `query`, `status`, and `index` fail loud with a clear "repos.csv not found" message on a missing gita repos.csv under every scope, including the default/repo scope (which previously showed a misleading "not inside a registered repo" hint); `index --corpus` scopes missing-dir warnings to that corpus
- **indexer**: fail loud on a configured/recorded embedding-model mismatch even when every source is unchanged; embed the heading together with the body so heading-only sections get non-empty vectors
- **client**: size embedding requests by total characters, not a fixed text count, and pass `-c`/`-b`/`--ubatch-size` when spawning `llama-server` - a run of long, token-dense chunks (transcript error turns, minified code) previously built a request past the server's default batch, which closed the connection and killed the whole index run
- **client**: `stop_served` releases the server engram currently owns at the lease's endpoint rather than signalling the lease's own pid - a lease goes stale the moment `embed()` recycles a degraded server (it keeps the fresh lease in a local while the caller still holds the pre-recycle pid), so stopping it signalled a dead process and left the replacement running; `harness.run_harness` holds a lease per candidate across a full scoring run, so the gold gate leaked a live embedding server for every candidate whose server recycled, and a leaked server outliving the process also made the next run lease it as unspawned and silently lose the degraded-server recycle
- **client**: size the embedding budget per model from the context the server reports, instead of applying one Qwen-derived constant to every candidate - `EMBED_MAX_CHARS` truncated every text at 8000 chars regardless of which model was serving, so a 2048-context model like `nomic-embed-text-v1.5` rejected a single dense chunk (~5225 tokens) with HTTP 400 and the eval gate could not compare models at all; the budget now comes from llama.cpp's `/props`, which reports the effective context even when spawned with a larger `-c` (llama.cpp clamps to the model's trained context), divided by a worst-case token density and capped by the existing ceiling, so a roomy model such as Qwen keeps exactly its previous 8000 chars and an endpoint that does not serve `/props` keeps the static budget
- **client**: keep owning a spawned embedding server across calls, and reap a sick one before replacing it - `ensure_served` leased an already-healthy endpoint as `spawned=False` even when engram had started that server itself, so every call after the first disowned it and the recycle above never fired; and when its own server degraded into refusing requests, the replacement could not bind the port the sick one still held, so readiness probes burned the full 120s timeout and the run died anyway
- **client**: recycle an embedding server that degrades mid-run instead of aborting the index - `llama-server` under sustained real load starts answering HTTP 200 with an all-null embedding array and can stay poisoned for every later request, so a null-bearing response now reaps the spawned server, respawns it, and retries the request once before failing loud; a server engram did not spawn is never restarted, and a replacement that is also degraded fails rather than looping
- **client**: refuse off-machine HTTP redirects (preserving the loopback-only invariant); reject an empty embedding shortlist or an unknown pinned id at config load; raise a clear error on a non-list `data` response field or a non-mapping `data` element (instead of a raw `AttributeError`); reap the spawned server when it reports the wrong model
- **eval**: the rg baseline fails loud on an rg error instead of silently zeroing (no false-positive gate); emit per-model, per-corpus hit rates; the scorer closes its sqlite connection; pinning the winner fails loud when the config has no `[pinned]` section
- **store**: `status` no longer reports harvested findings as stale or dead - findings hash their record body rather than their source file, and that source is expected to be trashed, so `engram status` previously exited nonzero forever once anything was harvested; findings rows are still counted in `row_count`, and staleness for every other corpus is unchanged
- **cli**: a failure while preserving findings across `index --rebuild` now prints `rebuild failed: ...` and exits 1 instead of raising a traceback, closing the temp store and removing the leftover rebuild database; the live database is left untouched either way
- **harvest**: a `PermissionError` (or any other `OSError`) while resolving a file's repo now yields a `no_repo` outcome for that one path instead of aborting the whole batch, restoring the per-file isolation contract; `--scope repo` and harvest also share one repo resolver, so findings stored under the `claude-home` sentinel are reachable from inside `~/.claude` instead of resolving to nothing
- **findings**: only an unreadable file (`OSError`) or malformed frontmatter (`yaml.YAMLError`) counts as a parse failure - any other exception now propagates with its own type and traceback instead of being masked as a routine `parse_failed` whose cause never reaches the harvest result; a whitespace-only `reviewers:` value is rejected like an empty one
- **indexer**: `index` commits each file's chunks as it goes instead of once at the very end - a long run that is killed or crashes now keeps everything it already embedded, and re-running it resumes from there instead of restarting from zero; an interrupted run also never prunes rows belonging to files it never reached
- **cli**: `pack --cycle` slugs its id with the same filename-safe rule `--diff` already applied, so a traversal id like `../../x` can no longer read a diff outside `dev/local/tmp/` or create a stray `engram-pack-..` directory; `pack --diff` rejects a range beginning with `-` before git is invoked, instead of handing git an argument it would parse as an option (`--output=` writes files) - that up-front rejection is the actual defense; every `git diff`/`git show` call the pack path makes also terminates its operands with `--`, which disambiguates revisions from paths, not option parsing
- **pack**: a `--prd` or `--capsule` path that cannot be read is now disclosed at the top of the rendered pack, naming the path, instead of being dropped in silence - a typo'd flag previously thinned every reviewer's Task prose with no signal anywhere and still exited 0. A capsule that reads fine but has no `## Active Work` section is unchanged: that is absence of content, not a failed read, and it is not disclosed. The note renders alongside the changed-symbols-omitted line rather than inside Task prose, so the section's own token cap cannot trim the disclosure away
- **diffmap**: a changed line that resolves to no enclosing function or class now contributes ONE file-level symbol for its file, anchored at the first such line, instead of one per changed line - a 20-line CHANGELOG edit previously produced 20 near-identical file symbols that the `(path, name, line_start, line_end)` dedup could not collapse, and since CHANGELOG sorts first, a docs-heavy diff burned the whole 40-symbol pack cap on single-line junk queries and crowded the real code symbols out. The cap is per file, so a diff touching several grammarless files still contributes one symbol each, and genuine function and class symbols in the same file are unaffected
