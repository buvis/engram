### 1 of 16 · MEDIUM · The embedding server engram starts keeps running after every command

**What.** Each `index`, `query` or `nudge` call that has to start llama-server leaves it running when the command exits. The code is in `src/engram/client.py` (`ensure_served` spawns with `start_new_session=True`; only `harness.py` calls `stop_served`). Walter and wendy both found it, and heidi and peggy saw it too.

**Evidence.** Walter: after the first `index`, `pgrep` showed pid 40818 on port 18101. About 20 engram calls later the same pid 40818 was still there, and only a manual `pkill` removed it. README.md:255-256 says "Engram spawns and stops the server itself when nothing is serving." Confidence: confirmed.

**If unchanged.** Every machine that runs engram keeps a llama-server with a loaded model in memory until it reboots or someone kills the process. This happens every time and stays the same, but the README tells users it does not. Side effect, inferred only: later calls lease a server they did not spawn, so the degraded-server recycle (the CHANGELOG fix) never fires.

**Options.**
1. **Fix the README to say the server stays up on purpose** (PRD 00001 asked for a detached spawn), and give the stop command. Benefit: truthful at once, and fast warm calls stay. Drawback: memory stays in use, and the recycle side effect remains. Effort S. Risk: none.
2. **Stop owned servers at CLI exit** (`atexit` calls `stop_served` for leases with `spawned=True`), and keep the server up for `mcp`. Benefit: matches the README. Drawback: every cold CLI call pays the spawn again (peggy measured 1-4.6 s). Effort M. Risk: `nudge` hooks get slower.
3. **Idle timeout**: the spawned server exits after N minutes without a request. Benefit: warm calls stay fast and memory comes back. Drawback: needs a watchdog process or a llama-server flag. Effort M-L (guess). Risk: a race between the timeout and a new request.
4. Accept or defer.

**Recommendation: option 1, then decide on 3 later.** The detached spawn was a design choice, so the doc is the defect. The strongest point against: a user who reads only the README still gets a resident 0.6B model nobody told them about until they read the new line.
